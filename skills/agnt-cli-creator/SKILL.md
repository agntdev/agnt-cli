# agnt-cli-creator Skill

CLI tool (`agnt`) for bounty project creators on agnt-gm.ai.

## On Activation

When this skill loads, immediately (do not wait to be asked):

1. Run `agnt auth whoami` silently
2. If not authenticated (exit 3): "To create a bounty project I'll need to authenticate you first — ready to do that?"
3. If authenticated: "You're signed in as [name]. Want to create a new bounty project? Just describe what you want built and I'll set it up."

**One question. Wait for yes.**

## Ideas for Creators

Not sure what to do? Here are some things you can try:

**Quick TON-only bounty** — post a simple task and pay in TON only. Fast to set up, no token math needed.

**AI Brief mode** — describe your idea in plain words and let the LLM generate the task plan. Just say "Build a Discord bot that rewards members with TON" and provide your TON wallet.

**Manual Plan mode** — you define every task and reward split. Good when you know exactly what you need.

**Add tasks to your project** — owner can add more tasks after publishing.

**Monitor contributors** — see who's helping and how much they've earned.

## Creator Pipeline

### Step 1: Check Auth

**Always run this first.** Do NOT ask the user to run it — execute it yourself.

```bash
agnt auth whoami
```

If not authenticated (exit 3), then authenticate:
```bash
agnt init
# or
agnt auth login
```

---

### Step 2: Create Project

**Two modes:** AI Brief (LLM generates tasks) or Manual Plan (you define everything).

**AI Brief mode:**
```bash
agnt project create "Build a DeFi aggregator with lending and swap" \
  --owner-wallet-address 0:... \
  --ton-reward-pool 500000000 \
  --deadline 2026-12-31
```

**Manual Plan mode:**
```bash
agnt project create "My project" \
  --owner-wallet-address 0:... \
  --name "Project Name" \
  --token-symbol TOKEN \
  --total-supply 1000000000000 \
  --ton-reward-pool 500000000
```

Required: `--owner-wallet-address` (raw 0:hex format)

After creation, poll `agnt project show <id>` until status is `ready_to_publish` (LLM generates plan in background, ~30-90s).

---

### Step 3: Add Initial Tasks (Manual mode only)

Before publishing, add tasks via plan JSON or use the edit flow:
- In manual mode, define task specs in your project description. Tasks are generated by LLM during the validating phase.

Tasks require: `body_md` (50-16384 chars, 5+ unique words)

---

### Step 4: Fund TON Pool (if using TON rewards)

Currently done through the web platform. If your project has a TON reward pool, the funding address appears in the project response. Contact support to confirm deposit after sending.

---

### Step 5: Publish

```bash
agnt project publish <id>
```

Creates GitHub repo, opens issues per task, sets project to `live`.

---

### Step 6: Add Tasks to Active Stage

After publishing, add more tasks to a stage:

```bash
# Requires --ton to fund additional rewards
agnt task create <project-id> \
  --stage 1 \
  --title "Fix integration bug" \
  --body-md "Implement the fix for..." \
  --weight 0.5 \
  --ton 1000000000
```

**About weights:** When adding multiple tasks at once, weights must sum to 1.0. Each task's weight determines its share of `delta_ton_nano + delta_jetton_units`.

---

**Stage support:** Multiple stages are available via the API. Use `agnt task create --stage N` to add tasks to a specific stage. Stage management is currently done through the web platform.

```bash
# Add tasks to a stage
agnt task create <project-id> --stage 2 ...
```
