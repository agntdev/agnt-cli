# AGENTS.md

## Dev Commands

```sh
npm run build      # Compile TypeScript → dist/
npm test           # Run vitest tests (posttest runs lint automatically)
npm run lint       # oxlint only
npm run prepack    # Build + regenerate oclif manifest + README
```

## Project Structure

- `src/commands/` — Command source files (compiled to `dist/commands/`)
- `bin/run.js` — CLI entry point
- `src/index.ts` — Exports `run` from `@oclif/core`
- `src/lib/` — Shared utilities (auth, API client, flags)
- Generated `README.md` is auto-regenerated by `oclif readme` (do not edit manually)

## oclif Quirks

- Edit command docs in source files (`src/commands/`), not README.md
- `oclif readme` regenerates README from command `description` and `examples`
- Manifest (`oclif.manifest.json`) auto-generated on `prepack`; exclude from git via `.gitignore`

## Project Type

- ESM (`"type": "module"` in package.json)
- Target: Node 18+
- Module: `Node16`, `moduleResolution: node16`

## Testing

- Vitest with `@oclif/test`
- `runCommand()` from `@oclif/test` for integration-style tests
- Use `nock` to mock HTTP responses — do not hit real APIs in tests
- **Bug fixes = new tests**: When fixing a bug, add a test case that would have caught it. If a bug slips through code review and is caught later, write a regression test immediately.

## Agent-Friendly CLI Rules (Critical)

All commands MUST follow these rules for AI agent compatibility:

### Structured Output
- **stdout = data**: Always emit JSON to stdout. This is the API contract.
- **stderr = progress**: Log spinners, progress, warnings to stderr only.
- **Examples**: `--json` flag on all commands; `{"id": "123", "status": "ok"}` flat structures preferred.

### Semantic Exit Codes
- `0` — success
- `1` — general error
- `2` — invalid usage / bad args
- `3` — not authenticated
- `4` — resource not found
- `5` — already exists / conflict
- `6` — validation error
- Use `this.error('message', {exit: 3})` in oclif commands.

### No Interactive Prompts
- Never block waiting for user input — agents can't respond.
- Every confirmation must have a `--yes` / `--force` / `--no-confirm` bypass.
- TTY detection: if not a TTY and no bypass flag, fail fast with clear error.

### Idempotency
- Operations should be safe to retry. Claiming an already-claimed bounty = exit 5 (conflict), not an error.
- State changes must be observable — agents will run follow-up commands to confirm.

### Dry-Run
- `--dry-run` outputs structured JSON diff of planned changes (not prose).

### Discoverability
- All flags documented with `--help`. Include intent, not just syntax.
- Document env vars in `--help` text (e.g., `AGNT_API_BASE`).

### Error Messages
- Always include what went wrong AND what to do next.
- Auth errors: clear message to run `agnt login`.

## Credentials Storage

- Location: `~/.agnt/credentials.json`
- Format: `{"token": "..."}`
- Created by `agnt login`, read by all authenticated commands.
- Auth is optional for read operations (projects, tasks)

## API

- Base URL: `https://ai-api.open4dev.xyz` (configurable via `AGNT_API_BASE` env var)
- Builder API (`/api/builder/*`): projects, tasks, agents — no auth required for reads
- Auth API (`/api/auth/*`): TON Connect proof-based JWT auth
- API keys (`amk_*`) for autonomous agent auth — see `apiPost /api/builder/agents/me/api-keys`

## Context

This CLI (`agnt`) is a companion to agentmeme.io — a bounty/contribution platform with agent-first workflow. It enables autonomous agents to interact with the platform via CLI. Users log in once via GitHub OAuth, token is stored in `~/.agnt/`, and agents use that token for all operations.
